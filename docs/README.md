# 知识库索引（Repository Knowledge Map）

这份目录是**给改代码的人**的：设计、依赖、调研。给**下载者**的文档在仓库根（`README.md` /
`SECURITY.md` / `PRIVACY.md`），它们进便携包；这一目录**故意不进包**，理由见最后一节。

## 五层知识，各归各的

| 层 | 放在哪 | 里面是什么 | 谁在读 |
| --- | --- | --- | --- |
| 为什么这么写 | 每个源文件的**头注释** | 局部决策、被否掉的写法、这一处踩过的坑 | 改这个文件的人 |
| 产品怎么用 | `README.md` | 装、跑、核哈希、能力边界、出 release | 下载者 |
| 坑与平台事实 | `PITFALLS.md` | 只放别处没有的东西，逐条标 `[实测]/[调研]/[推理]` | 维护者 |
| 结构、依赖、调研 | `docs/`（本目录） | 模块边界、不变量、决策记录、环境依赖、同类工具 | 维护者 / 审计者 |
| 逐轮过程与数字 | `CHANGELOG.md` | 每轮改了什么、量到了什么数 | 问"这条结论是哪次跑出来的"的人 |

**新增一条知识时，先问它属于哪一层**（放错层的代价是这件事以后没人找得到）：

- 只在这一个文件里成立的事实 → 那个文件的头注释。
- 下载者会问的 → `README.md`。
- 换个项目也成立、而且很容易重犯的坑 → `PITFALLS.md`。
- 跨文件的**结构或约定**（谁负责什么、什么不许破、要装什么） → `docs/`。
- 只是"这一次量到了多少" → `CHANGELOG.md`。

## 证据规则（这个仓库的知识必须可复读）

1. **每条结论带标记**：`[实测]` 真跑出来的（附可复跑的入口）／`[调研]` 查一手来源得来的（附来源）／
   `[推理]` 没测过，明说，别当结论用。
2. **引用哪一次运行，就说哪一次的**：写"CI 印出 86 通过"时必须指明是哪个 commit / 哪次 run，因为
   下一条改动就可能让它不再是那个数。`README.md` 的探针表里同时存在**历史末行**（引用当时的输出，
   保持原样）和**当前数字**（清单条目数这类，会随仓库变），两种情况分开写。
3. **引用就必须能重读**：名点一个日志、一个 pid、一行输出，它就得能从盘上或 API 上再读一遍。
   本仓库因此保留了一批 `_tmp/*.log` 取证记录（`_tmp/` 是 gitignore 的，只存在于开发机）——
   **清理 `_tmp` 前先 grep 文档、把被点名的路径列成保留名单**，命令与那次实测的规模写在
   `PITFALLS.md` §五 末尾。
4. **一条断言必须配一条能把它弄红的注入腿**：只"绿过"的东西不算验证过。自检探针就是干这个的
   （`tests/probe-*-selftest.ps1`、`tests/probe-procwalk.ps1`、以及 `probe-native` 普通运行自带的那条腿）。

## 为什么 `docs/` 不进便携包

`tests/ka-release-files.ps1` 的规矩是：**仓库根的文件都要被某条规则认领，被认领的根文件就进 zip**
（那正是 `favicon.svg` 当初掉队的地方）。这一目录不在根、也不被清单点名，所以它只在 GitHub 上——
下载者拿到的是产品，不是维护笔记。要让它进包，就得把它写进那份 `$docs` 名单；写在这里是为了下次有人
问"为什么 `docs/` 不在 zip 里"时不必猜。
